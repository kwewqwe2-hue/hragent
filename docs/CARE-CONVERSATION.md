# 关怀对话引导

关怀回复先接纳感受，再询问当前需要，每轮只提供少量可选步骤。支持短暂休息、了解休假安排、沟通工作量、回应沟通受阻、只倾诉、专业支持和 HR 协助等路径。

连续对话中的“但是我没假期了”等表达作为当前困难处理，记录用户自述的无可用假限制，不推算实际余额、不自动检索其他假期。后续休息建议保留该限制，用户更正后解除；“年假还没用完”和明确询问制度等情况不误判。未识别的关怀续话先温和澄清，明确政策、业务或新话题请求才退出关怀。普通交谈减少反复菜单，每轮尽量使用两三句、最多一个问题。

回应以事实、影响、需求和可协商方案为中心，不推断公司或主管恶意，不无依据替任何一方辩解，不鼓动报复、编造事实或冲动决定。正常休假、如实反馈、申诉和外部求助不受限制；人身安全优先于企业声誉。

聊天中的关怀选择不自动发请假申请、不自动联系 HR 或创建普通工单。明确点击开始申请后仍沿用填写、核对、确认提交流程；现有紧急风险转介机制保持优先。申请填写中的明显情绪倾诉先进入关怀，不写入申请字段。

多轮引导仅缓存企业、员工、会话及阶段，15 分钟到期。不缓存原始倾诉，不做心理诊断、情绪评分或离职预测。普通聊天历史仍受现有客户端存储规则约束，不能承诺绝对保密。EAP 渠道来自企业实际配置，服务方保密范围和可用性需由用户查看确认。

设计参考：[WHO 工作场所心理健康指南](https://www.who.int/publications/i/item/9789240053052)，关注员工支持、工作安排及管理沟通，不代替专业评估。

验证：后端 227 项测试；`scripts/test-care-guidance.cjs` 验证实际接口和页面的关怀链路、倾诉偏好及支持渠道；政策对话回归通过。危机场景仅使用 mock 验证，未创建演示危机工单，普通关怀验收前后申请与工单记录保持一致。
