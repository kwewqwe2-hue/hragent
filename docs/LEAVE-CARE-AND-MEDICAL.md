# 对话请假、病假材料与审核动态

明确办理表达（如“我想休年假”“想请病假”）优先进入 LifecycleService 的对话草稿。年假先读取包含审批占用的实际可用余额；缺失余额不推测为零，余额不足不创建申请。制度咨询仍走政策问答。

病假填好假别、日期、原因后，通过助手专用上传入口，或请假表单中的材料入口上传 PDF/JPG/PNG（5 MB 上限）。PDF 文字提取和图片 OCR 使用部署在内部网络的已有解析服务，不发送到通用聊天或 n8n 执行历史。扫描版 PDF 无文字时提示改传清晰图片。自动初检检查文档类型、姓名、医疗机构、日期与基本诊疗信息；不判断诊断、不鉴定真伪、不代替人工核验医嘱与请假期限。识别失败时不生成成功材料记录、不提交审批。

原始文件和识别文本均加密存储。材料绑定员工、企业空间和本次日期；修改日期须重新上传。LeaveService 统一拦截未提供材料的病假提交，避免从工作台、对话或接口绕过；绑定时锁定记录，避免并发重复使用。员工确认后才提交。主管和 HR 在原有审批页查看原件；病假保留 HR 人工审核，不走主管自动备案捷径。文件下载仅限本人、对应主管和本空间在职 HR，记录访问审计，不在提醒中展示诊断。

助手的“请假审核动态”和“我的服务单”每 5 秒查询本人记录。标签页隐藏时暂停，恢复可见后同步；身份切换清除旧数据，卸载停止计时。初次加载展示当前状态，不把历史申请当作新提醒；断网提示同步中断并重试。审核通知位于独立区域，不打断正在填写的对话。员工也可直接问“我的请假批了吗”获取真实状态和审核意见。

启动解析依赖：`docker compose -f n8nwork/docker-compose.yml up -d --no-deps pdf-parser ocr`。后端默认内部地址为 `http://hragent-n8n-pdf-parser:3000/extract` 和 `http://hragent-n8n-ocr:8000/ocr`，可用 `app.medical.pdf-url` / `app.medical.ocr-url` 配置。后端须可访问 `n8nwork_default` 网络；这些解析端口不对宿主机公开。

验证包括 Java 对话路由、真实余额缺失/耗尽、材料检查失败、姓名/日期匹配、所有权与空间隔离、日期变更、重复绑定、统一病假提交拦截和保留 HR 审核。浏览器测试拦截业务写入，使用合成材料及模拟状态变化，避免在真实员工账号留下测试申请或医疗材料。
