# 员工日常服务与自助办理

> 页面调整已按用户要求撤回，下面是此前功能实现记录，其中新增面板入口已停用。当前原页面中的知识库接入见 [手册知识库](HANDBOOK-KNOWLEDGE.md)。后端服务保留。

本次功能入口：SaaS 的「员工服务中心」和独立聊天端侧栏的「员工服务 · 自助办理」。两个入口使用同一套后端权限和业务数据。

## 已实现

- 制度问答按当前登录员工的工作城市、职级、工种、合同主体匹配；仅引用当前企业、已审核、有原文出处、已生效且未失效的制度。
- 出处、生效日期和发布日期独立展示；属性缺失时不会匹配受该属性限制的制度。未找到依据时提示 HR 补充，不编造政策或员工权益。
- 在职证明、收入证明的申请、审批、下载；收入证明强制包含本人档案中的税前月薪。文件附企业盖章/电子签章指引，当前没有对接真实电子签章供应商。
- 社保、公积金异地转移及落户准备清单：输入城市后生成可下载的 Markdown，并附已匹配依据。没有官方指南时明确为待核实的准备提示，不判断申请资格。
- 转正答辩提前 30 天、合同续签提前 60 天、体检预约提前 30 天、年假到期提前 60 天生成站内提醒；每日北京时间 08:00 检查，打开页面时同步，页面每分钟刷新。
- 提醒去重、已处理/重新打开、明天提醒、ICS 日历导出；档案日期变化后旧提醒停用；没有日期则不推算。处理提醒不代表劳动合同、转正或预约业务已办结。

## HR 配置

1. 在「员工服务 → HR 维护」选择员工，维护城市、职级、工种、合同主体和提醒日期。合同到期日读取原有个人档案。
2. 在「知识库」维护原文和出处，填写生效日期、可选失效日期、原文链接，以及地区/职级/工种/合同主体范围。多个值使用逗号分隔；范围留空为当前企业全员适用。城市按名称精确匹配，允许“上海”与“上海市”等后缀差异；不自动推断省市从属关系。
3. 正式政策未经 HR 核实，不应仅为了显示答案而填写生效日期。已有文章不会把发布日期自动当作生效日期。
4. 体检链接由 HR 维护。年假到期提醒使用当前假期台账余额和 HR 维护的到期日，不自动清零余额。多年度结转额度仍需后续对接分年度假期台账。

## 聊天与运行模式

新增常用业务查询直接访问后端数据，不依赖 n8n 或大模型。证明办理请求会引导到可确认用途的表单，避免将“咨询”当成“提交”。

`hragentv1/.env` 的 `WEB_CHAT_WORKFLOW_ENABLED=false` 启用独立员工服务模式：未配置模型时显示“员工服务模式”；HR 在「AI 配置」保存有效模型连接后可启用后端模型对话。

需要原有 n8n 办理工具、钉钉和附件解析时，按主 README 绑定模型凭据、内部 Agent Key、工作流和解析服务，再将 `WEB_CHAT_WORKFLOW_ENABLED=true` 并重建后端容器。此开关只控制网页聊天编排，不修改 n8n 工作流和数据。站内提醒不自动向钉钉或邮箱发送消息。

本地本次检查发现模型 Key 和 n8n 内部 Key 为空，因此当前采用员工服务模式。普通问候、制度查询、年假余额、证明进度、关键事件提醒可直接使用；自由模型对话仍需 HR 配置模型。

## 验证与维护

前端共享组件以 `hragent-chat/src/components/EmployeeServices.vue` 为源。修改后运行 `powershell -ExecutionPolicy Bypass -File scripts/sync-employee-services-ui.ps1`，同步到 SaaS 前端，再分别执行 `npm run build`。

后端新增政策匹配与提醒测试，并扩展收入证明测试。`scripts/test-employee-services.mjs` 是本地演示环境验收脚本，使用 README 中的演示账号；会生成一份明确标注的演示收入证明。员工匹配档案会恢复，测试制度会转为草稿，证据保存在忽略目录 `.artifacts/employee-services`。

2026-09-07 本地验证：后端 73 项测试通过，9 项真实接口验收通过；两个 Vue 前端及 Docker 镜像构建成功。浏览器验证覆盖问答、证明列表、清单下载、提醒、390px 手机视口、SaaS 服务入口，无 JavaScript 运行错误。
