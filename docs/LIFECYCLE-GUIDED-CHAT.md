# 全周期对话办理

Agent AI 支持输入或点击“入职、在职、离职、离职后”，获得对应服务菜单。阶段选择只读取指引，不创建申请；离职后身份仅提供允许办理的事项。办理动作来自后端固定服务定义，不来自模型生成的可执行命令。

`WebChatDtos.MessageResponse.actions` 是可选的结构化按钮列表，旧的三参数构造保持兼容。`LifecycleService.guidedReply` 在同一事务内处理对话和生成下一步按钮；保留原有行锁和确认提交逻辑。`LifecycleNavigation` 提供阶段菜单与限定页面路径。

填写时显示步骤编号、常用选项、上一步、查看草稿及取消。填写完整后才能出现确认提交；可回到指定字段修改，后续字段清除并重新核对，避免日期或证明类型的相关值沿用错误。浏览服务阶段、问制度或查看个人数据不会被静默写成表单答案。原有 HR/主管审批与文件生成仍负责正式办理结果。

前端保留按钮在对话历史中，仅最新助手回复中的对话按钮可用，发送中禁用。页面跳转仅允许四个现有工作台路径，不接受任意外部地址；交接入口直接打开离职准备。对话按钮不会附带输入框中未发送的附件。现有在线页面独立填写，不自动复制或提交对话草稿。

验证包括四阶段导航、原截图“在职”、对话/企业隔离、字段校验、回退修改、未确认不提交、重复确认不重复创建、离职后权限，以及既有全生命周期单元测试。浏览器验证使用真实只读菜单请求和拦截的表单写入，不产生真实员工测试申请。
