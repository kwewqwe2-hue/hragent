# 员工主入口：Agent AI

统一入口 `http://localhost:5173/` 跳转 `/agent/`，原 `5174/` 兼容跳转至该入口。工作台保留原有业务路由，通过助手左侧“前往工作台”进入。员工在旧登录页登录后默认进入助手，HR 和平台管理入口保留。

两个 Vue 客户端通过同一来源的 localStorage 共享账号和当前企业，不把凭证放进 URL。助手发起的业务仍使用现有 API 和权限检查；切换企业或登出时同步助手上下文。前端聊天存储仍按账号/企业隔离。

支持的方式：
- 请假、证明、人事变更、社保公积金、合同、离职等沿用全周期对话草稿和确认流程。请假进入主管审批，证明进入原证明管理，其余咨询/申请进入 HRSSC。
- 查询自己的信息、请假记录、工作计划和提醒直接调用已有业务服务。任务完成和提醒处理先显示确认，再更新同一数据记录；只操作本人当前清单。
- 资料明细、通讯录、材料清单、附件/模板上传、证明下载、入职登记、关怀、反馈、申诉和账号设置在助手内部办理面板完成。它们复用真实工作台表单，不伪装成已经由聊天完成。敏感申诉仍通过原有明确同意表单提交，文件仍经既有上传接口处理。
- 管理操作保持现有角色权限。员工没有 HR 审核、批量导入或成员管理权限；不能通过对话或面板获得额外权限。
- 请假消息与审批：主管和 HR 在 Agent AI 顶部打开待办弹窗，查看申请与病假材料，填写意见并确认通过或驳回；主管通过后转 HR，HR 完成审核后员工收到结果动态。详情见 [Agent AI 请假消息与审批](AGENT-LEAVE-APPROVALS.md)。

面板路径由固定允许列表控制，框架同源加载，不接收任意外站 URL。复杂表单仍需用户在助手面板填写/确认，当前不声称所有管理员功能已变成自由文本命令。模型不能直接执行任意 API。

验证覆盖默认路由、旧端口兼容、同源登录和退出、助手内表单加载、前往工作台、阶段导航和任务确认/企业隔离。业务写入验收使用单元测试或浏览器拦截，不创建演示用假申请。
